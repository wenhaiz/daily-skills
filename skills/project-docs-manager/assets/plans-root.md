# 开发计划

这里保存尚未完成的功能计划。已完成的 Plan 移到 [`archived/`](archived/README.md)，主目录只保留仍需继续处理的工作。

创建 Plan 前，先检查当前目录和 `archived/` 是否已有同一任务。优先继续已有的活动 Plan；没有仓库命名约定时，新文件使用 `yyyy-MM-dd-<kebab-title>.md`。

每份 Plan 都是自包含、持续更新、以可观察结果为目标的活文档。至少记录：状态、目的、仓库上下文、范围外事项、实施步骤、带时间的进度、意外与发现、决策、验证结果、结果回顾和 ProductFact 收口情况。

复杂功能、重要重构、跨模块改动、迁移、长时间任务、存在明显未知项或需要分阶段验证时，使用完整 ExecPlan。完整要求见 [`PLANS.md`](PLANS.md)，创建时从 [Plan 模板](../0-ProductFact/90-templates/plan-template.md) 开始。

状态使用：`draft`、`active`、`blocked`、`completed`、`superseded`。

开发期间持续维护同一份 Plan。每个停顿点都更新进度、已完成内容和剩余工作；出现意外或改变方案时，同步更新发现、决策及受影响的其他章节，保证新执行者只读当前仓库和 Plan 就能继续。

验收必须证明可观察行为或可复现的测试结果，不能只记录编译通过或文件发生变化。自主继续执行不得越过用户授权、仓库规则、审批或危险操作边界，也不要求未经授权的提交。

只有最终行为已经同步到 ProductFact 并完成必要验证后，Plan 才能标记为 `completed`。

Plan 明确标记为 `completed` 后，保留原文件名移到 `archived/`，并同步更新仓库内引用。状态缺失或不明确时不要推断为已完成。
